Pick a layout for your config items

Same field, nine layouts. Each emphasizes different parts of the field — sometimes the name and value should dominate; sometimes the metadata should. Pick one (or two — list view + detail view is a common combo) and the library will use it for every field in your config.

How the library would expose this

Pick one layout per view in your config.viz.json. A common pattern is two: a list_view (e.g. Compact row or Postcard) for scanning, and a detail_view (e.g. Headline or Recipe card) for when someone drills in. You can also pick different layouts per section — flat scalars get tiles, nested objects get YAML, list-of-objects get cards.
